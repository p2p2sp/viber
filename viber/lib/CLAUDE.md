# viber/lib - the Node core of the plugin's scripts, behind four ports

Owns the Node modules holding script logic (the config core under `config/`, `arg-kind.ts`, `switch-text.ts`, `attach-lines.ts`, `summary-path.ts`, `strip-tag.ts`, `skill-part.ts`, `handoff-path.ts`, `qa-ledger.ts`, `run-changes.ts`, `tree-record.ts`, `diff-files.ts`, `run-failures.ts`, `synthesize.ts`, `reach.ts`, `plan-text.ts`, `plan-build.ts`, `extension.ts`, `frame.ts`, `lint_skill.ts`, `keep-units.ts`, `hunt-return.ts`, `rules-map.ts`, `memory-map.ts`, `merge-settings.ts`, `commit.ts`, `commit-context.ts`, `archive-run.ts`, `worktree.ts`, and the helpers two of them share, `abs-path.ts`, `stamp.ts`, `byte-order.ts`, `repo-prefix.ts`, `plugin-root.ts`, `run-header.ts`, `hunt-brief.ts`, `map-answer.ts` and `commit-args.ts`), the port types and their real adapters. It owns no entry (`../scripts/<name>.ts`, `../skills/<skill>/scripts/<name>.ts`) and no fake (`tests/harness/fakes.ts`).

## Terms

- Core: every module outside `adapters/` and `ports.ts`; it imports no file system, process, network or OS module and reaches the outside only through a port.
- Port: `Fs` (reads `readText`, `readBytes`, `size`, `exists`, `kind`, `realPath`, `listDir`, `executable`, `isLink`; writes `setExecutable`, `makeDir`, `writeBytes`, `appendBytes`, `replace`, `move`, `removeTree`, `remove`, `removeEmptyDir`), `Git` (`repoRoot`, `isRepository`, `trackedFiles`, `branch`, `commit`, `shortCommit`, `indexHolds`, `headHolds`, `stagedFiles`, `report`, `symbolicRef`, `mergeBase`, `firstAdded`, `changedFiles`, `untrackedFiles`, `trackedIgnored`, `ignored`, `status`, `grep`, all reads), `GitWrite` (`stageTracked`, `stage`, `stageAll`, `commit`, `move`, `removeTracked`, `addWorktree`, `removeWorktree`, `pruneWorktrees`) and `Clock` (`now`) in `ports.ts`. The ports for GitHub and the environment arrive with the first script that needs them.
- Adapter: `adapters/fs.ts` (`nodeFs`), `adapters/git.ts` (`gitCommand`), `adapters/git-write.ts` (`gitWriteCommand`) and `adapters/clock.ts` (`systemClock`); the first two map every failure to the port's empty answer (`null`, `false`, an empty list), the third answers git's exit status. `adapters/path-chunks.ts` cuts a path list for both git adapters.

## Relationships

- `config/run.ts` `runConfig(argv, cwd, ports)` is the one public entry of the config core: it returns the whole stdout and never throws. `../scripts/config.ts` calls it with the adapters and prints; `../scripts/config.sh` runs that entry.
- `arg-kind.ts` `runArgKind(argv)` touches no port and returns stdout, stderr and the exit code; `switch-text.ts` `runSwitchText(argv, cwd, ports)` takes its value from `runConfig` and returns the whole stdout. Each has its entry `../scripts/<name>.ts`, run by the wrapper `../scripts/<name>.sh`.
- `attach-lines.ts` `runAttachLines(argv, cwd, ports)` (`Fs`, `Git`) and `summary-path.ts` `runSummaryPath(argv, cwd, ports)` (`Fs`, `Git`, `Clock`) return stdout, stderr and the exit code; `strip-tag.ts` `runStripTag(argv, ports)` (`Fs`) returns nothing. Entries and wrappers: `../scripts/attach-lines.ts`, `../skills/intent/scripts/summary-path.ts` and `../skills/code-auditor/scripts/strip-tag.ts`, each beside the `.sh` of its name.
- `skill-part.ts` `runSkillPart(argv, cwd, ports)` (`Fs`, `Git`) calls `runSwitchText` in process for each fragment block and takes `pluginRootOf` from `switch-text.ts`; `qa-ledger.ts` `runQaLedger(argv, cwd, script, ports)` (`Fs`) takes the path its entry was started by (`process.argv[1]`) and cuts the plugin root from it; both return stdout, stderr and the exit code. `handoff-path.ts` `runHandoffPath(argv, cwd, ports)` (`Fs`, `Git`, `Clock`) returns the whole stdout. Entries and wrappers: `../scripts/skill-part.ts`, `../skills/handoff/scripts/handoff-path.ts` and `../skills/e2e/scripts/qa-ledger.ts`, each beside the `.sh` of its name.
- `run-changes.ts` `runRunChanges(argv, cwd, ports)` (`Git`), `tree-record.ts` `runTreeRecord(argv, cwd, ports)` and `diff-files.ts` `runDiffFiles(argv, cwd, ports)` (both `Fs`, `Git`) return stdout, stderr and the exit code. Entries and wrappers: `../scripts/run-changes.ts`, `../skills/fixer/scripts/tree-record.ts` and `../skills/code-auditor/scripts/diff-files.ts`, each beside the `.sh` of its name.
- `run-failures.ts` `runRunFailures(argv, cwd, ports)` (`Fs`, `Git`) takes the archive directory from `runConfig` in process; `synthesize.ts` `runSynthesize(argv, ports)` (`Fs`) derives every path from its workspace argument. Both return stdout, stderr and the exit code. Entries and wrappers: `../scripts/run-failures.ts` and `../skills/code-auditor/scripts/synthesize.ts`, each beside the `.sh` of its name.
- `plan-build.ts` `runPlanBuild(argv, cwd, script, ports)` (`Fs`, `Git`, `Clock`) takes the path its entry was started by, reads `build.memory` from `runConfig` in process and calls `runStripTag` in process on every agent file before it reads it; it returns stdout, stderr and the exit code. Entry and wrapper: `../skills/planner/scripts/plan-build.ts` beside `plan-build.sh`.
- `plan-text.ts` (`parsePlan`, `slicesOf`, `rangeOf`, `linesOf`, `textOf`, `listOf`; no port) and `reach.ts` (`collectReach(targets, root, git)`, `targetPath`; `Git.grep` alone) serve `plan-build.ts` and have no entry of their own. `parsePlan` reads the plan text and checks nothing: validation stays with `../scripts/plan-index.sh`.
- `extension.ts` `runExtension(argv, cwd, ports)` (`Fs`, `Git`) takes its `LISTED` and `MISSING` values from `runConfig` in process and finds the map with `mapClassifier` of `config/lines.ts`; `frame.ts` `runFrame(argv, cwd, script, ports)` (`Fs`, `Git`, `Clock`) settles the diff scope through `runDiffFiles` in process and cuts the skill directory from the path its entry was started by; both return the whole stdout. `lint_skill.ts` `runLintSkill(argv, ports)` (`Fs`) returns stdout, stderr and the exit code. Entries and wrappers: `../skills/extension/scripts/extension.ts`, `../skills/code-auditor/scripts/frame.ts` and `../skills/skill-designer/scripts/lint_skill.ts`, each beside the `.sh` of its name.
- `keep-units.ts` `runKeepUnits(argv, script, ports)` and `hunt-return.ts` `runHuntReturn(argv, script, ports)` (both `Fs`) call `runStripTag` in process and take the run, the unit and seed lines, the ledger append and the hunter block from `hunt-brief.ts`, which reads run.md through `headerValue` of `run-header.ts`; `rules-map.ts` `runRulesMap(argv, cwd, script, ports)` (`Fs`, `Git`, `Clock`) takes the archive directory from `runConfig` in process. All three take the path their entry was started by and return stdout, stderr and the exit code. Entries and wrappers: `../skills/code-auditor/scripts/keep-units.ts`, `../skills/code-auditor/scripts/hunt-return.ts` and `../skills/rules/scripts/rules-map.ts`, each beside the `.sh` of its name.
- `memory-map.ts` `runMemoryMap(argv, cwd, script, ports)` (`Fs`, `Git`, `Clock`) takes the path its entry was started by; `merge-settings.ts` `runMergeSettings(argv, cwd, ports)` (`Fs`, `Git`) merges, creates and resets the settings file. Both return stdout, stderr and the exit code. Entries and wrappers: `../skills/memory/scripts/memory-map.ts` and `../skills/setup/scripts/merge-settings.ts`, each beside the `.sh` of its name.
- `commit.ts` `runCommit(argv, cwd, ports)` (`Fs`, `Git`, `GitWrite`) and `commit-context.ts` `runCommitContext(argv, cwd, script, ports)` (`Fs`, `Git`; the whole stdout) read the selector through `readSelector` of `commit-args.ts`; `archive-run.ts` `runArchiveRun(argv, cwd, ports)` takes the two directory keys from `config/lines.ts` and `directory` of `config/block.ts`; `worktree.ts` `runWorktree(argv, ports)` takes no cwd. The last two take `Fs`, `Git` and `GitWrite`; all but `commit-context` return stdout, stderr and the exit code. Entries and wrappers: `../skills/commit/scripts/commit.ts`, `../skills/commit/scripts/commit-context.ts`, `../scripts/archive-run.ts` and `../skills/code-auditor/scripts/worktree.ts`, each beside the `.sh` of its name.
- `map-answer.ts` (the answer, the refused call, `projectRoot`, `baseOf`) serves `rules-map.ts` and `memory-map.ts`; `merge-settings.ts` takes its answer type and `projectRoot`, `commit.ts`, `archive-run.ts` and `worktree.ts` its answer type.
- `plugin-root.ts` `rootAbove(script, levels)` cuts the skill directory or the plugin root for `frame.ts`, `qa-ledger.ts`, `hunt-brief.ts`, `rules-map.ts`, `memory-map.ts`, `commit-context.ts` and `plan-build.ts`.
- `abs-path.ts` `absolutePath(path, cwd)` spells a path one way for `attach-lines.ts`, `qa-ledger.ts`, `run-changes.ts`, `diff-files.ts`, `merge-settings.ts` and the `--files` paths of `memory-map.ts`; `stamp.ts` `stampOf(at)` is the file name stamp of `summary-path.ts`, `handoff-path.ts`, the reach candidates file of `plan-build.ts` and the map ids of `rules-map.ts` and `memory-map.ts`; `byte-order.ts` `byteOrder(a, b)` sorts the path lists of `tree-record.ts` and `diff-files.ts` and the report and rule names of `run-failures.ts` and the rules, areas and trails of `rules-map.ts` and the nodes and candidates of `memory-map.ts`; `repo-prefix.ts` `repoPrefix(dir, root, fs)` places the cwd of `tree-record.ts` and `commit-args.ts`, the root argument of `diff-files.ts` and the run directory of `archive-run.ts` below the repository root. A helper gets a module of its own once a second core needs it.
- `tools/lint/run.ts` reads its tree through the same adapters.
- Tests: `tests/viber/config/<module>.unit.test.ts` per config module, `tests/viber/lib/<module>.unit.test.ts` per module outside `config/` (the `layering/core` rule holds both), `tests/viber/lib/fakes.unit.test.ts` and `tests/viber/lib/adapters.integration.test.ts`.

## Contracts

- The key grammar of `.claude/viber.yml` and every stdout line live in the header of `../scripts/config.ts`; the modules of `config/` split it: `lines` (groups and children), `block`, `extensions`, `branching`, `reports`, `local`.
- A fake and its adapter pass the same contract cases (`fsContract`, `gitContract`, `gitWriteContract`, `clockContract` in `tests/harness/ports-contract.ts`).
- `Fs.readText` and `Fs.readBytes` answer `null` for an absent path, a directory and an unreadable file alike. `Fs.kind` follows a symlink and answers `null` for anything but a regular file or a directory; `Fs.realPath` answers forward slashes, the spelling `Git.repoRoot` gives.
- `Fs.executable` answers whether this account may run the file: `false` for a file carrying no exec bit and for an absent path, `true` for every existing file on a system that keeps no such bit (Windows).
- `Git.branch` answers the short name of the branch HEAD stands on, one with no commit yet included, and `null` on a detached HEAD or outside a repository.
- `Git.changedFiles`, `untrackedFiles` and `status` take the top level of the work tree and answer repo-relative paths read from git with `-z`: a blank, a quote, a backslash or a non-ASCII character arrives as it is, a rename as its new path alone. `changedFiles(root, null)` compares against the empty tree. `Git.firstAdded` reads its path as a literal one, never a glob. `Git.commit`, `symbolicRef` and `mergeBase` answer `null` for a ref that names nothing.
- `Fs.makeDir`, `Fs.writeBytes`, `Fs.appendBytes`, `Fs.replace`, `Fs.remove` and `Fs.removeEmptyDir` answer `false` in place of throwing; `replace` renames a file over another in one step and takes no directory; `appendBytes` never rewrites what the file holds, so two calls at once lose no ledger line, and `removeEmptyDir` takes no link and no directory holding an entry; `writeBytes` replaces the content in place and creates no directory, and `remove` is `true` for an absent path and `false` for a directory.
- `Fs.size` reads no content: `memory-map.ts` counts every tracked file with it. `Git.trackedIgnored` lists the tracked files the ignore rules exclude; `Git.ignored` judges one path by the rules alone, the index left out.
- `GitWrite` reads every path as a literal one, relays git's output on the standard error of the process as it comes (the worktree calls hand it back) and runs hooks and signing as any git call. `commit` with paths builds a private index, so the user's other staged work stays staged; its path is `<git dir>/index.viber-commit.<pid>`, left behind only by a killed process.
- `Git.stagedFiles` answers `null`, never an empty list, when git cannot tell; `Git.report` is text for a person, git's error in front of it.
- `Fs.move` takes a file, a directory or a link and never replaces what stands at the target (`replace` does, files only); `Fs.removeTree` follows no link.
- `Git.grep` reads the work tree, never a commit: tracked and untracked text files, an ignored and a binary one left out, each term a fixed string, a whole word under `word`. It reads git with `-z`, so a path arrives as it is and a colon in one splits nothing; no term and no repository answer the empty list.
- The core reads the local-time fields of `Clock.now()`: a unit test builds its instant from local fields (`new Date(2026, 10, 24, 17, 14, 16)`), so it holds in every time zone.

## Change together

- A port method: `ports.ts`, its adapter, its fake in `tests/harness/fakes.ts` and the contract cases with their scene state.
- A config key or report line: the header of `../scripts/config.ts` and the module that resolves it, with its unit test.
- A switch key: the `KEYS` set of `switch-text.ts`, the header of `../scripts/switch-text.ts` and the switch table of `tools/lint/data/invocations.ts`.
- An entry under `../skills/<skill>/scripts/`: its path in the `entries` list of `tools/lint/data/layering.ts`, named whole.
- The planner work file names under `.temp/viber/planner/`: the `WORK` pattern of `plan-build.ts` (what a survey removes, unless `--phase` goes on with the plan surveyed last, whose outline printed a split proposal) and the scratch list of `archive-run.ts`.
- The slice cut (`ceil(n / 8)` runs, sizes differing by at most one, the larger first): `slicesOf` of `plan-text.ts`, the review lines of `../scripts/plan-index.sh` and `../hooks/scripts/plan-gate.sh`.
- The task block markers and the `- <Label>: <value>` field lines `parsePlan` reads, and the ones `../scripts/plan-index.sh` validates.

## Traps

- `Fs.exists` is true for a directory: a directory named `<name>.md` under `.claude/agents/` counts as a found extension agent.
- A `.claude/viber.local.yml` that is a directory prints `# local: none | ignored: none`: the port cannot tell a directory from an unreadable file.
- A value is cut at the first blank or `#`: a quoted name holding a blank reports its cut text. An empty quote pair for a title gives the default.
- The red-check lists cut a value at a blank followed by `#`, `--questions` at the first blank or `#`: the two rules differ on purpose.
- `runSwitchText` hands the skill directory to `Fs.readText` as given, so a relative one resolves against the process cwd in the adapter; `runStripTag` hands each file path on the same way, `runSkillPart` its part file, and `runHandoffPath` its `.md` target to `Fs.exists` as written (`..` and `./` kept), so the system follows a link before a `..` after it.
- `runSynthesize` hands its workspace and the lens file `run.md` names to `Fs` as written, and `runRunFailures` joins a relative run directory to the repository root as written (`..` and `./` kept), so the system follows a link before a `..` after it.
- `runSynthesize`, `runRunFailures` and `runPlanBuild` read every file as UTF-8 text and write what they read back as UTF-8: a byte that is no valid UTF-8 in a report, a hit line or the plan reaches `findings.md`, `failures.md`, the candidates file or the plan file as U+FFFD. The ledger alone is appended to as bytes.
- `runPlanBuild` rewrites the plan through `linesOf` and `textOf`: `merge` and `apply` leave every line ending on a line feed, a carriage return dropped, and `skeleton` also drops the blank lines at both ends of the plan text. `plan_part_sum` drops the carriage return too, so a checksum taken before such a write still matches.
- `runPlanBuild` compares the plan path of a `survey --phase` with the one of its state file as text, and hands every file path of its arguments to `Fs` as written.
- `collectReach` skips a search term shorter than 3 characters (`skipped:`) and keeps at most 200 hit lines per target and 200 characters of each, counted in characters, never bytes; a target with an empty path gets no section.
- A `- Blocking [<cause>]` word is lower-cased letter by letter in ASCII (`runRunFailures`): a full Unicode fold would turn a Kelvin sign into `k` and admit a cause that is none.
- The fake file system matches a path as text: `runAttachLines` and `runQaLedger` make an argument absolute and drop `.`, `..`, doubled and trailing slashes themselves (`absolutePath`) before they ask a port, and a core module that prints a path it looked up does the same.
- `absolutePath` resolves `..` as text, before any symlink is followed: `link/../x` names the sibling of the link, not of the directory it points to.
- `byteOrder` orders by code point, the order of the UTF-8 bytes `LC_ALL=C sort` gave: the default sort of a string array differs from it for a character past U+FFFF against one of U+E000..U+FFFF.
- The git adapter decodes every path as UTF-8: a file name that is no valid UTF-8 arrives with U+FFFD in place of its bad bytes.
- `runRunChanges` hands a run directory that does not read as below the root to `Git.firstAdded` as written, so git follows a link before it refuses the path; `runDiffFiles` answers `NOT_A_REPO` inside a `.git` directory and in a bare repository, where `Git.repoRoot` finds no work tree.
- `runQaLedger` counts a length in code points: a column of accented text stays aligned, a wide character still takes two cells on screen.
- The runtime converts an argument that is one path, never a path inside a list: `readSelector` reads `/c/...` as `C:/...` itself under a drive root. It converts the argument `/` to the directory Git is installed in, so `worktree.sh` refuses it before node.
- `runCommit` ends on git's own exit of the first step that failed and prints nothing then; a path outside the repository is `Nothing to commit`. A new file whose name is no valid UTF-8 fails the staging of a named directory; the whole-tree commit takes it.
- A `/c/...` argument never reaches a core under Git Bash: the MSYS runtime hands node `C:/...`, so `runHandoffPath`, `runQaLedger`, `runTreeRecord`, `runFrame`, `runKeepUnits`, `runHuntReturn`, `runRulesMap`, `runMemoryMap`, `runMergeSettings`, `runArchiveRun`, `runWorktree` and `runPlanBuild` hold no MSYS rule, and the `refs:` lines of `qa-ledger`, `rules-map`, `memory-map` and `plan-build` (its `plan:` line too) and the skill and plugin paths of `frame`, `keep-units`, `hunt-return` and `commit-context` read `C:/...` whichever spelling invoked the wrapper.
- `runExtension` splices the two lines of `--add` into the bytes of `viber.yml`: a byte that is no valid UTF-8 elsewhere in the file stays as it is, and a write that fails answers `STATUS=stale`, never `added`.
- `runFrame` asks `Fs.kind` for the root itself when the scope is the root, never `<root>/.`, and prints the `RUN:` line even when the workspace could not be written.
- `runKeepUnits` and `runHuntReturn` hand their workspace and the lens file `run.md` names to `Fs` as written. The score files are read in name order, `S1-retry.md` before `S1.md`.
- `runRulesMap` tells a link by its real path, as `runLintSkill` does but ignoring case: it lists a linked `.md` file, enters no linked directory and reads a linked `.claude/rules` or archive as empty.
- `runMemoryMap` reads a node it cannot open as 0 bytes, yet counts an unreadable file toward its candidate directory (`Fs.size` needs no read right); a submodule entry counts toward none.
- `runMergeSettings` names no system error: the port answers `false` or `null`, so its messages say which path could not be read, created or written. `writeBytes` keeps no file mode: the settings backup takes the default one.
- `runLintSkill` takes no cwd: a relative target resolves against the process cwd in the adapter and is printed as given. It tells a link by its real path (an entry whose `Fs.realPath` is not its directory's real path plus its own name) and neither reads nor follows one.
- `runStripTag` reads the last line as one byte per character: a byte outside ASCII on that line never counts as a blank or a tag character.
- The map lines of `build.extensions` are classified in `config/lines.ts`, and `readChildren` skips them, so no map line is read as a child of `build:`.
