# Resume a draft or a roadmap

A draft the user points at - a landed plan carrying a specification and not one task block - is resumed, not interviewed again. Read that file first, then ask only about what the round of remarks changed: everything the draft already states is settled and costs no question. Ask through one `AskUserQuestion` which this round is: another draft round to circulate, or the task half on top of the settled specification. Close on the same confirmed summary, stating that round decision and naming the draft's run key so the next round lands in its own directory.

A `roadmap.md` the user points at is resumed the same way: its first entry with no `(built)` or `(this plan)` marker is the next part, and its listed decisions are settled and cost no question. Ask only what the builds since changed and that part's open unknowns. A part is never a release: nothing is published until the last part is built, so never ask what works between parts, how to ship this one, or what stands in for a later part - no stub, mock or temporary alternative. The summary carries that part's decisions as settled, the later parts as boundaries, and closes on the line `Roadmap: <repo-relative path of roadmap.md>`.

When that entry's first indented line is `Issue: <full issue URL>`, that URL is the run's issue from the start: the branching start step and the summary's `Issue:` line carry it. An entry with no such line ties the run to no issue.
