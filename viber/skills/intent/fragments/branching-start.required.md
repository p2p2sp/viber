Settle the run branch before reading any code. Run `"${CLAUDE_PLUGIN_ROOT}/scripts/plan-path.sh" --start` as one literal Bash line with the flags the input carries and no others: `--draft "<plan path>"` for a returning draft (read it first, per `## Returning to a draft`), `--pr` for an input naming a `review.md` under `.temp/viber/pr-feedback/`, `--roadmap` for a `roadmap.md` the user points at, and `"<issue URL>"` last when the run is tied to an issue. The report decides; this step only shows or asks what it says.

- `mode: off` -> say nothing about branches; hand off no branch line.
- Show every `error:` and `note:` line, in the conversation's language.
- `next: settled` -> the `settled:` value stands. An entry key: show one run branch line, never opening with `Work:` or `Branch:`, holding the key, the branch (its `name:` pattern), its `base:` and its `target:` from its `entry:` line. `no-branch` ("no branch"), `current` ("build on `current:`") and `pr` ("pull request branch"): show one line saying no run branch is made and commits land on `current:`.
- `next: ask-entry` or `next: ask-base` -> ask through one `AskUserQuestion` with one option per `option:` line, described by its last field; at most four options, any further one by free text.
- `next: none` or `next: abort` -> hand off no branch line; `abort` also stops here.
- `next: errors` -> nothing is asked; hand off no branch line.
- An answer to `ask-entry`: an entry key -> run the same `--start` line again with `--entry <key>` added; `abort` -> stop and run nothing else.
- An answer to `ask-base`: `switch` -> run `"${CLAUDE_PLUGIN_ROOT}/scripts/plan-path.sh" --checkout "<branch>"` as one literal Bash line, the branch being that option's second field, and on success settle the `checking:` entry. `stay` -> settle the `checking:` entry, moving nothing. `current` -> "build on `current:`" is settled. `abort` -> stop and run nothing else.
- A `--checkout` failing with exit 6 -> show its error. When it names uncommitted changes, tell the user to commit or stash first and ask the same question again. Any other failure: ask the same report's options again without `switch`.
- A new issue saved after this step (the `ISSUE_URL=` of `issue-create.sh`; after an issue set save, this cycle's part sub-issue URL, and no re-run when that one did not land or `mode: off`) -> right after that save and before the "what next" question, run the same `--start` line once more with the same flags plus `--settled <settlement>` and the new issue URL in place of the earlier one. The settlement is the entry key, `no-branch`, `current` or `pr` last settled, `nothing` when none was. Handle its report as above. `next: kept` -> the earlier settlement stands, nothing new is shown. `next: errors` with a `settled:` line -> that settlement stands.
