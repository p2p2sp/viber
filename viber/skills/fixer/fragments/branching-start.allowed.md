Settle the run branch before tracing or reading any code. Run `"${CLAUDE_PLUGIN_ROOT}/scripts/plan-path.sh" --start --fixer` as one literal Bash line, adding `"<issue URL>"` last when the report was read from an issue. The report decides; this step only shows or asks what it says.

- `mode: off` -> say nothing about branches; hand off no branch line.
- Show every `error:` and `note:` line, in the conversation's language.
- `next: settled` -> the `settled:` value stands. An entry key: show one run branch line, never opening with `Work:` or `Branch:`, holding the key, the branch (its `name:` pattern), its `base:` and its `target:` from its `entry:` line. `no-branch` ("no branch") and `current` ("build on `current:`"): show one line saying no run branch is made and commits land on `current:`.
- `next: ask-entry` or `next: ask-base` -> ask through one `AskUserQuestion` with one option per `option:` line, described by its last field; at most four options, any further one by free text.
- `next: none` or `next: abort` -> hand off no branch line; `abort` also stops here.
- `next: errors` -> nothing is asked; hand off no branch line.
- An answer to `ask-entry`: an entry key -> run the same `--start --fixer` line again with `--entry <key>` added; `no-branch` -> "no branch" is settled, shown as above; `abort` -> stop and run nothing else.
- An answer to `ask-base`: `switch` -> run `"${CLAUDE_PLUGIN_ROOT}/scripts/plan-path.sh" --checkout "<branch>"` as one literal Bash line, the branch being that option's second field, and on success settle the `checking:` entry. `current` -> "build on `current:`" is settled. `abort` -> stop and run nothing else.
- A `--checkout` failing with exit 6 -> show its error. Before the reproduction test exists and when it names uncommitted changes, tell the user to commit or stash first and ask the same question again. Once the reproduction test exists, the uncommitted test is what blocks the switch: ask the same report's options again without `switch`, and with `abort` alone left, say why and stop. Any other failure: ask the same report's options again without `switch`.
- When the save step creates an issue, right after that save and before the hand-off, run the same `--start --fixer` line once more with `--settled <settlement>` and the `ISSUE_URL=` value of that save as the issue URL. The settlement is the entry key, `no-branch` or `current` last settled, `nothing` when none was; `mode: off` earlier -> do not run it again. Handle its report as above. `next: kept` -> the earlier settlement stands, nothing new is shown. `next: errors` with a `settled:` line -> that settlement stands.
