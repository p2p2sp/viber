# viber/skills - the twenty-two viber skills and their bundled files

Owns every `skills/<name>/` directory: its `SKILL.md` and the `fragments/`, `parts/`, `templates/`, `references/`, `assets/` and skill-local `scripts/` beside it. The plugin-level scripts the skills call belong to `viber/scripts/`, the agents they dispatch to `viber/agents/`; a skill's own body is its contract.

## Terms

- Preload: a ```` ```! ```` fenced block or a `` !`...` `` line in a `SKILL.md`, run by the shell when the skill loads, its stdout standing in its place before the model reads a word. A non-zero exit aborts the whole skill load, so every script used as a preload exits 0 in every data condition.
- Part: `skills/<skill>/parts/<name>.md`, a stretch of a skill's steps that its `SKILL.md` prints on demand with `scripts/skill-part.sh` instead of holding it in context from the start; `implementor` has `close` (steps 5 to 7), `intent` has `done`.
- Hand-off lines: the labelled lines carried verbatim into `planner`'s input (`intent` saves it as the summary file `summary-path.sh` names and passes the path, passing it as text inside plan mode; `fixer` passes text): `Issue: <URL>` (intent, fixer), `Attachment: <absolute path under .temp/>` (written by prototype for its mockup, printed by `scripts/attach-lines.sh` for each existing `.temp/` path in the input of intent and fixer, carried through intent), `Work:` / `Branch:` (the `branching-handoff` fragments of intent and fixer), `Phases: <path>` (intent resuming a `phases.md`).

## Relationships

- Who starts a skill: `planner` and `implementor` carry `user-invocable: false`; `e2e`, `extension`, `handoff`, `memory`, `pr-feedback`, `pr-feedback-reply`, `rules`, `setup` and `talk` are user-only (`disable-model-invocation: true`); every other skill the model may invoke, `pr-create` only on the user's request or yes.
- Skill to skill: `prototype` invokes `intent`; `pr-feedback` invokes `intent` with the path of its `review.md` and two requirements (one task per chosen thread or remark, each task's DoD writes its reply file) as text, not a hand-off line; `intent` invokes `prototype` on the user's yes to a screen decision or to `Prototype first`; `intent` and `fixer` invoke `planner`; `planner` invokes `intent` only to split a change past 30 tasks or 60 files, with the `Split proposal:` block `plan-build.sh outline` printed after the confirmed input, and names `implementor` as the next step, never invoking it; `implementor` invokes `pr-create` on the user's yes once a finished build on a pull request branch closes the last phase; `talk` invokes nothing and ends on suggesting `/viber:handoff` or `/viber:issue-create`; `code-auditor` invokes no skill and, with a confirmed finding, ends on the line `/viber:intent <absolute path of findings.md>`; `extension` invokes `skill-designer` once on the files it writes, skipping the step when the skill is not in its listing.
- Agents each skill dispatches: `implementor` (`task-coder`, `task-reviewer`, `arbiter`, `test-runner`, and through its close fragments `final-reviewer`, `memory-writer`, `rules-writer`, `qa-writer`, `closeout`, plus every `build.extensions` agent by its bare name), `planner` (`plan-surveyor`, then one `plan-author` for a whole plan, or `plan-architect` for the frame and one `plan-author` per slice, then `plan-judge` once per review round; a fix is a new dispatch of the `plan-author` or `plan-architect` owning the text; each sent the block `plan-build.sh` prints; and `adr-screener` through `planner/references/adr-tasks.md`), `intent` (the built-in `Explore` for repository facts), `prototype` (`prototype-writer`), `talk` (`researcher`), `e2e` (`e2e-writer`), `memory` (`memory-auditor`, `memory-node-writer`), `rules` (`rules-auditor`, `rules-writer`), `code-auditor` (`mapper`, `scout`, `hunter`, `critic`). `outside-plan-review` runs only on the plan gate's request.
- A skill-local `scripts/<name>.sh` with a `<name>.ts` beside it is a wrapper running that entry (contract in the entry header, core in `../lib/`): nineteen, each entry named in `tools/lint/data/layering.ts`. Logic by `tests/viber/lib/<basename>.unit.test.ts`, wrapper by `tests/viber/<basename>.critical.test.ts` (`plan-build.sh` alone has no wrapper test). `handoff-path.sh` and `extension.sh` are preloads: each exits 0 always and prints nothing without `node`. `rules-map.sh` and `memory-map.sh` do so with no argument, their preload; a call with one ends on the exit of its entry. `merge-settings.sh` without `node` creates and resets the settings file by plain copies of its own and prints the recommended block in place of a merge: a change to the create or the reset goes to `../lib/merge-settings.ts` and to it. `commit-context.sh`, a preload, exits 0 always and without `node` prints one `STOP:` line, so the fork commits nothing.
- Files read across skill directories: `memory` reads `setup/templates/claude-md-prompt.txt`.
- Child nodes: `ui-designer/CLAUDE.md`, `skill-designer/CLAUDE.md`.
- Tool dependencies: `code-auditor` needs only git and a POSIX shell beside the plugin's Node.js; `e2e` needs `playwright-cli` and `@playwright/test`, reported by `scripts/check-playwright.sh` and installed only on the user's yes; `ui-designer` states its own Node.js needs in its node.

## Contracts

- Every `switch-text.sh` call in a `SKILL.md` or a `parts/*.md` names a key of `switch-text.sh`'s list and a `<name>` with a `fragments/<name>.<value>.md` for at least one valid value; every fragment file is named by a call in its own skill's `SKILL.md` or `parts/*.md`. Values: `true` / `false`, except `off` / `fast` / `full` for `build.baseline-tests`, `off` / `allowed` / `required` for `branching.mode` and `off` / `on` for `build.extensions`.
- A `branching.mode` call is written `branching.""mode`: the shell joins it into the one word `branching.mode`, and the `invocations` lint rule strips the quotes to read the key. A new call copies that spelling.
- A fragment reaches the model as `switch-text.sh` prints it: Claude Code substitutes nothing in a preload's output, so the script expands only `${CLAUDE_SKILL_DIR}` and `${CLAUDE_PLUGIN_ROOT}`; `$ARGUMENTS` or any other variable in a fragment stays literal.
- The hand-off lines become plan frontmatter: the writer of the specification half (`plan-architect` in a frame, else the `plan-author` of a whole plan) fills `issue:` from `Issue:`, `attachments:` (a map of unique file or directory name to source path) from the `Attachment:` lines and `source:` always; `planner` adds `work:` and `branch:` from `Work:` / `Branch:` through its `branching` fragments, by one `Edit` after a `Read` of the frontmatter alone. `scripts/plan-path.sh` reads those keys when it lands the plan.
- `planner` and `implementor` decide nothing a script can: `planner` reads no code and composes no plan text (`planner/scripts/plan-build.sh` moves the files, counts the two review rounds and says what comes next), and `implementor` opens no file and starts only the tasks `scripts/task-step.sh` lists on its `ready` call. The sections hold their rules.
- A part is printed by one literal `skill-part.sh` call that the skill's `allowed-tools` lists and its body makes before the first action that needs the part.
- Scripted steps answer in directive lines the skill acts on as printed (`memory` and `rules` compose no auditor brief: `memory-map.sh --targets`, `--reconcile`, `rules-map.sh --brief`, `--confirm` print each `NEXT:` block): `fixer/scripts/tree-record.sh` records the changed paths by name, never content; `e2e/scripts/app-wait.sh` never launches the application (the launch stays the model's background Bash call); `e2e/scripts/qa-ledger.sh` never writes `qa.e2e.md`, whose `## Automation` lines only `e2e-writer` writes.
- Temporary files: a skill's own under `.temp/viber/<skill>/`, matched by an `Edit(./.temp/viber/<skill>/**)` allow where it edits there; `implementor` gives each task `.temp/viber/<task-id>/`, `memory` and `rules` use `.temp/viber/<map id:>/`, `pr-feedback` and `pr-feedback-reply` `.temp/viber/pr-feedback/<pull request number>/` (none committed), `code-auditor` `.temp/viber/code-auditor/<run-id>/`. `planner` edits nothing under `.temp/viber/planner/`: `plan-build.sh` keeps its state and work files there, and a planning agent or the judge writes there only outside plan mode, to its `out:` path; in plan mode it writes the plan file the harness names for it.
## Commands

- Preload quoting, the exec bit of every bare-invoked script and the fragment calls above: `node tools/lint/run.ts invocations`.

## Change together

- A hand-off line: the body or fragment writing it (`intent`, `fixer`, `prototype`, `scripts/attach-lines.sh` for `Attachment:`), `planner/SKILL.md` and its `branching*` fragments, and `scripts/plan-path.sh`.
- The `Same defect elsewhere` field of the `fixer` diagnosis: its `picked` / `not picked` marks, which `planner`'s agents read from the diagnosis text alone, and `fixer`'s step 5 question.
- The `Split proposal:` block (phases, `Open decisions:`): printed by `plan-build.sh outline` from the `PHASE:` and `DECIDE:` lines of the `plan-surveyor` outline, only beside a `threshold:` line, passed on as printed by `planner/SKILL.md` and read through `intent/references/split.md`, whose `## From a split proposal` keeps the input's hand-off lines and skips the branch start and issue saves for it.
- The five items a root `CLAUDE.md` names (build, whole suite, single test file, fast command, layer marker convention): `setup/SKILL.md`'s check, `setup/templates/claude-md-prompt.txt`, `references/node-doctrine.md`'s Root and the `MISSING:` vocabulary of `agents/memory-node-writer.md`.
- The extension contract: `extension/templates/extension.md` (the `<!-- viber:extension -->` marker, the `run:` / `spec:` / `notes:` / `out:` lines, `VERDICT: WRITTEN | NONE | FAIL | DENIED`), the marker test in `viber/lib/extension.ts` and the dispatch lines `scripts/plan-index.sh --split` prints (`lib/plan-index/run.ts`) in each `NEXT: extension` block, which `implementor/fragments/extensions.on.md` sends as printed.

## Traps

- `intent`'s start text (`SKILL.md` plus the fragments the template defaults select) is word-capped by `tests/viber/intent-prose.unit.test.ts`: added words fail that test until the cap is raised on purpose. The interview text that is read only at the end belongs in `parts/done.md`.
- Skill arguments reach a preload by text substitution before the shell runs: `commit` passes `'$ARGUMENTS'` and `handoff` `'$0'`, single-quoted so `$`, backticks and backslashes stay literal. An apostrophe in the arguments breaks the preload, and `$0` arrives as the literal `$0` when no argument came.
