# viber/hooks - the guard hooks' scanning traps

Read for a change to `kill-guard.sh`, `shell-guard.sh` or `verdict-nudge.sh`: how they scan a command or a message, and what they allow and refuse. The rules every hook shares (exit 0, fail open) stay in the node.

## Contracts

- `kill-guard.sh` acts only for a top-level `agent_type` starting `viber:`, denies `killall`, `pkill`, `taskkill` with `/IM`, `xargs ... kill` and `kill` fed by a command substitution in command position, and never answers `allow`.
- Every refusal of `kill-guard.sh` and `shell-guard.sh` opens `viber guard:`, the marker the agents' tools paragraph reads as a correction to apply, never a denial. `shell-guard.sh` acts only for `viber:task-coder` (R1 an unquoted `;`, `&&` or `||`; R2 `git` `stash`, `checkout`, `restore` or `clean`; R3 `rm`, also through `xargs`; R4 a file write through `Bash`: `sed -i`, `perl -pi`, a redirect or `tee` onto a relative path outside `.temp/`; R5 inline interpreter code - `python -c`, `node -e`, `ruby -e`, `perl -e` - or a `.temp/` script run through an interpreter, `bash` and `sh` included) and for `viber:task-reviewer` and `viber:final-reviewer` (R2 only); the rationale of each rule lives in its header, not in the agents. The R1, R3 and R4 reasons end on the corrected command (`Run instead: ...`) when one derives from the refused one; a quote, `$`, glob, newline, `sed -i`, `perl -pi`, `tee` or a second redirect gives none, and so does an R1 chain holding `||` or one setting state for a later part (`cd`, `pushd`, `export`, `source`, `.`, `NAME=value`); the R2 and R5 reasons carry none.
- `verdict-nudge.sh` blocks a stop once when the agent's type starts `viber:` and is none of `scout`, `mapper`, `hunter`, `stop_hook_active` is not true, a final message is present and no line of it opens, after whitespace and any `` ` ``, `*` or `-`, with `VERDICT:` or `AUDIT:`, with one fixed instruction; one pattern both finds that line and reads its value, skipping blanks, `` ` `` and `*` after the colon (`**VERDICT:** PASS`, `VERDICT:PASS`). It reads the `VERDICT:` values from `../agents/<name>.md`, found beside a script invoked by a `\` path too; when that file names any, the last `VERDICT:` line of the message holding none of them is blocked too, the reason listing them (a last `AUDIT:` line passes). A skill's fallback for a second reply without the line stays with the skill.

## Traps

- `kill-guard.sh`, `shell-guard.sh` and `verdict-nudge.sh` run on every `Bash` call or agent stop of every session: a call from outside the agents they act on must return on bash builtins alone, before any external command. All three set `LC_ALL=C` and scan by byte: in a UTF-8 locale a 20 KB command took 5 s against the 10 s timeout. `kill-guard.sh` and `verdict-nudge.sh` unescape the JSON in one left-to-right awk pass (`kill-guard.sh` passes the value through `ENVIRON`, `verdict-nudge.sh` on stdin, since Linux caps one env string at 128 KB and a longer message made awk fail) because bash 3.2 (macOS `/bin/bash`) rescans the string per `${var//x/y}` match, which ran an 11 KB command past the timeout; `shell-guard.sh` still unescapes with `${var//}`, with the same cost, after `shopt -u patsub_replacement` (bash 5.2 otherwise eats a backslash in a replacement and expands `&`).
- `shell-guard.sh` treats an unquoted newline as no chain, a `#` opening a word as a comment, `>&2`, `>&-`, `2>&1` and an absolute or `.temp/` redirect target as no write, `>&file` and `N>&file` onto a relative path as a write, and `git rm`, the exec-bit `git update-index` and a quoted `rm` as allowed.
- `shell-guard.sh` R5 reads an option cluster letter by letter and ends it at a letter taking an attached argument, so `python -m pytest`, `node --test`, `ruby -Itest` and `perl -Ilib` run; the first argument that is no option is the script, checked for `.temp/`. `python -m`, `bash -c`, `bash -s` and a lone `-` end the scan unrefused. A node long option taking a separate value ahead of `-e` is skipped only when listed (`--require`, `--import`, `--loader`, ...): an unlisted one hides the code. `perl -pi` stays R4; `perl -ne` and `perl -MList::Util -e` are R5.
