# viber/hooks - editing the guard hooks

Read for a change to `kill-guard.sh`, `shell-guard.sh`, `verdict-nudge.sh`, `file-guard.sh` or its entry `scripts/file-guard.ts`: how they scan a command, a message or a payload, and what they allow and refuse. The rules every hook shares (exit 0, fail open) stay in the node.

## Contracts

- `kill-guard.sh` acts only for a top-level `agent_type` starting `viber:`, denies `killall`, `pkill`, `taskkill` with `/IM`, `xargs ... kill` and `kill` fed by a command substitution in command position, and never answers `allow`.
- Every refusal of `kill-guard.sh`, `shell-guard.sh` and `file-guard.sh` opens `viber guard:`, the marker the agents' tools paragraph reads as a correction to apply, never a denial. `shell-guard.sh` acts for `viber:task-coder` (R1 an unquoted `;`, `&&` or `||`; R2 `git` `stash`, `checkout`, `restore` or `clean`; R3 `rm`, also through `xargs`; R4 a file write through `Bash`: `sed -i`, `perl -pi`, a redirect or `tee` onto a relative path outside `.temp/`; R5 inline interpreter code - `python -c`, `node -e`, `ruby -e`, `perl -e` - or a `.temp/` script run through an interpreter, `bash` and `sh` included) and for `viber:task-reviewer` and `viber:final-reviewer` (R2 only), and for every `viber:` agent on R6 (a `cd` or `pushd` whose target holds an unquoted `*`, `?` or `[`, a `$` outside single quotes or a command substitution); the rationale of each rule lives in its header, not in the agents. The R1, R3 and R4 reasons end on the corrected command (`Run instead: ...`) when one derives from the refused one; a quote, `$`, glob, newline, `sed -i`, `perl -pi`, `tee` or a second redirect gives none, and so does an R1 chain holding `||` or one setting state for a later part (`cd`, `pushd`, `export`, `source`, `.`, `NAME=value`); the R2, R5 and R6 reasons carry none.
- `verdict-nudge.sh` blocks a stop once when the agent's type starts `viber:` and is none of `scout`, `mapper`, `hunter`, `stop_hook_active` is not true, a final message is present and no line of it opens, after whitespace and any `` ` ``, `*` or `-`, with `VERDICT:` or `AUDIT:`, with one fixed instruction; one pattern both finds that line and reads its value, skipping blanks, `` ` `` and `*` after the colon (`**VERDICT:** PASS`, `VERDICT:PASS`). It reads the `VERDICT:` values from `../agents/<name>.md`, found beside a script invoked by a `\` path too; when that file names any, the last `VERDICT:` line of the message holding none of them is blocked too, the reason listing them (a last `AUDIT:` line passes). A skill's fallback for a second reply without the line stays with the skill.
- `file-guard.sh` prints nothing unless stdin holds a top-level `"agent_type":"viber:task-coder"`; with no `node` it prints nothing either. It reads the first 4096 characters of the payload with a bash builtin and decides on them: a caller whose `agent_type` stands there leaves before the rest is read, and only a longer payload with no complete `agent_type` in that head (a main-session call) has its rest read, in blocks, by one command substitution. The core (`../lib/file-guard.ts`, contract in the header of `scripts/file-guard.ts`) refuses the edit of a path, made repo-relative, that the `Files` line or one of the two extras files (`work/<id>-extra.md`, `work/<id>-extra-review.md`) of another task on neither `done:` nor `skipped:` of `status.md` lists, unless the coder's own task lists it in its `Files` or in one of its own two extras files. A skipped task claims nothing: it never finishes, so the wait the refusal asks for could not end. Of several claimants the lowest-numbered is named, the path spelled as that task lists it. On darwin and win32, whose default file systems ignore case, the entry has the core compare paths without regard to case (`src/A.ts` is `src/a.ts`). `Files` come from the first `- Files:` line of each `<run>/tasks/<id>.md`, never from `plan.md`. The one deny line tells the coder to leave the file, finish every `DoD` clause that does not need it and return `VERDICT: FAIL` with `WAIT: <path>`. Everything else prints nothing: a path no open task claims, a path outside the repository, a dispatch with no `task:` line, a run with no `status.md`, any missing or unreadable input.
- The file guard finds the coder's task file in the first `task: <path>` line of the dispatch prompt, the `message.content` of the first record of the coder's own transcript, taken only when that record is a `user` one whose `agentId` equals the payload's `agent_id`. The transcript is, first found: the payload's `agent_transcript_path`; `<transcript_path less ".jsonl">/subagents/agent-<agent_id>.jsonl`; `transcript_path` itself when it is named `agent-<agent_id>.jsonl`. A relative task path is read against the repository root (the git top level of `cwd`, else `cwd`), then the `cwd`. The task file found is kept as the one line of `<root>/.temp/viber/guard/<agent_id>` and read back first on a later call, so the transcript is read once per coder; the run directory is the parent of its `tasks/` directory.

## Change together

- The file guard's refusal wording and `WAIT:` line: `../lib/file-guard.ts`, `../agents/task-coder.md` (its guard line and its `WAIT:` output line) and the `--wait` flag of `../scripts/task-step.sh`; `tests/viber/guard-prose.unit.test.ts` pins the wording.
- What claims a path for a task (its `Files` and its two extras files, until the task is done or skipped): `../lib/file-guard.ts`, the ownership check of `../scripts/commit-task.sh` (`claimants()`, `extras_claimants()`) and `../lib/task-ready.ts`.

## Traps

- `kill-guard.sh`, `shell-guard.sh`, `verdict-nudge.sh` and `file-guard.sh` run on every `Bash` call, agent stop or `Edit` and `Write` of every session: a call from outside the agents they act on must return on bash builtins alone, before any external command, so `file-guard.sh` starts `node` only past its `agent_type` filter. Bash reads a pipe one byte per system call: reading a whole payload with `read` cost 0.3 s per megabyte on macOS (1.7 s for a 5 MB `Write`), which is why `file-guard.sh` reads only a head that way. The first three set `LC_ALL=C` and scan by byte: in a UTF-8 locale a 20 KB command took 5 s against the 10 s timeout. `kill-guard.sh` and `verdict-nudge.sh` unescape the JSON in one left-to-right awk pass (`kill-guard.sh` passes the value through `ENVIRON`, `verdict-nudge.sh` on stdin, since Linux caps one env string at 128 KB and a longer message made awk fail) because bash 3.2 (macOS `/bin/bash`) rescans the string per `${var//x/y}` match, which ran an 11 KB command past the timeout; `shell-guard.sh` still unescapes with `${var//}`, with the same cost, after `shopt -u patsub_replacement` (bash 5.2 otherwise eats a backslash in a replacement and expands `&`).
- `shell-guard.sh` treats an unquoted newline as no chain, a `#` opening a word as a comment, `>&2`, `>&-`, `2>&1` and an absolute or `.temp/` redirect target as no write, `>&file` and `N>&file` onto a relative path as a write, and `git rm`, the exec-bit `git update-index` and a quoted `rm` as allowed. R6 reads the target with its quotes in place: `cd 'run*'`, `cd "run*"` and `cd run\*` pass, `cd "$RUN"` does not, and `cd`, `cd -`, `cd ~/x` and `cd ..` pass.
- `shell-guard.sh` R5 reads an option cluster letter by letter and ends it at a letter taking an attached argument, so `python -m pytest`, `node --test`, `ruby -Itest` and `perl -Ilib` run; the first argument that is no option is the script, checked for `.temp/`. `python -m`, `bash -c`, `bash -s` and a lone `-` end the scan unrefused. A node long option taking a separate value ahead of `-e` is skipped only when listed (`--require`, `--import`, `--loader`, ...): an unlisted one hides the code. `perl -pi` stays R4; `perl -ne` and `perl -MList::Util -e` are R5.
