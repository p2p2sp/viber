# viber/scripts - editing the scripts of the implementor's close

What `run-summary.sh`, `run-changes.sh`, `run-suite.sh`, `commit-task.sh --repair` and `--leftovers` and the `profile:`, `NEXT: extension`, `NEXT: qa-kept`, `--slice` and `--final-review` outputs of `plan-index.sh` check and print, so `implementor`, `closeout`, `test-runner` and `final-reviewer` keep only the rule to run each and act on its answer.

## Contracts

- `run-summary.sh [<started> [<run-dir>]]`: no argument prints `started:`, one the `elapsed:` line (`unknown` is a value), two the `elapsed:` line then the token report. More than two arguments or an empty run directory exits 2 with nothing on stdout; any other run directory problem still prints the `elapsed:` line first, and `implementor` then writes `tokens: unavailable`.
- The token report exits 0 with its `tokens:` lines or the one `tokens: unavailable - <reason>` line. It counts a transcript whose first line names `<runs>/<key>` followed by `/`, a backslash, a double quote or a space, from Claude Code's undocumented `subagents/agent-<id>.jsonl` layout, so a layout change reads as `unavailable`, never as an error. It never counts the `closeout` role nor a `<synthetic>` model line, opens no transcript last written before the day the run key names, and turns the whole report `unavailable` when one counted transcript cannot be read through.
- After the build rows it prints one `tokens:` row per role and model of the planning transcripts (`planner-review`, `planner-spec-review`, `planner-graph-review`, `planner-task-review`, `adr-screener`, `plan-surveyor`, `plan-architect`, `plan-detailer`, `plan-fixer`) whose first line names the `planned:` path of `plan.md`, each transcript counted once; it ends on one `rounds: plan review <n>` or `rounds: plan review unavailable - <reason>` line, `<n>` counting each `planner-review` and `planner-graph-review` dispatch once, a retry too, so it is an upper bound. A run landed before `plan-path.sh` wrote `planned:` reads `unavailable`.
- `commit-task.sh --repair <plan> <round> <file>...` routes each file itself: to the fix-number commit of the highest-numbered task whose `Files` lists it (a skipped one included), commits in ascending task number, every unowned file in one `fix(viber): post-test repair (round <n>)` commit last; a group with no change is skipped and exit 4 means none had one. Paths are folded by `named_path()` and a `.temp/` path refused. The round's trail rides in the first group that changes; a failing commit exits 5 after the earlier groups, with one `uncommitted: <path>` line per path of the failed group and every later one.
- `commit-task.sh --leftovers <plan> --drift <n>|none` reads `closeout`'s `outcome.md` (the summary and, last, the heading line) and runs `plan-index.sh` itself for its `skipped:`, `dirty:` and `orphan:` lines. It rewrites everything after the heading from those and its note links: a path names the lowest-numbered task (by number, `T3` before `T10`) whose `T*-coder`, `-extra` or `-extra-review` note holds it as a fixed-string substring. Only the two unexplained reasons are committed, under `OUTSIDE_SUBJECT` (shared with `--outside`) with one `Leftover: <path> | <reason>` body line each; an earlier call's committed lines are read back from those bodies. A trailing `Drift:` line marks a file this form wrote, whose heading and section lines are popped and rebuilt, so a rerun is safe. Exit 0 whatever the leftover outcome (a failed `plan-index.sh` is the one line `leftover check not performed: <its first FIX:, SPLIT: or error: line>`); exit 2 only for bad arguments or no `outcome.md`. It prints `committed: <sha>` when a commit landed, then `left: <n>` or `left: none`.
- `plan-index.sh --split` prints one `profile:` line per task neither done nor skipped, after the `verify:` lines, then the `NEXT: extension` blocks, then `NEXT: qa-kept`. A profile is read from `config.sh`'s `tiers.min` and `tiers.max`: no `verify:` line is read, so `waive?` and `haiku?` only mark eligibility, and the model confirms the build or test command. A `TDD: required` task never prints `waive?`.
- `plan-index.sh --slice <ids>` prints `commit:` and `file:` lines and writes nothing; `--final-review` prints one `NEXT: final-review` block per slice (or `NEXT: skip`), cut like the planner review slices, whose `scope:` line is the `--slice` call `final-reviewer` runs. Each refuses any other mode beside it with exit 2.
- `run-changes.sh [<run-dir>]` prints `base:` (the oldest commit adding `<run-dir>/plan.md`, `HEAD` with no argument, `none` and nothing more when none added it) and one `changed:` path per changed or untracked file, each as it is and never quoted (git is read with `-z`), a path with a newline unsupported; it is the wrapper of `run-changes.ts` beside it (core in `../lib/run-changes.ts`).
- `run-suite.sh run <report> <cmd-file>` runs the command file's command once into a log under `.temp/viber/test-runner/` ending on `exit=<code>`; `wait <report>` prints `log:` then `exit=<code>` or `NEXT: wait` at `RUN_SUITE_WAIT` seconds (default 590), and reads only a log at least as new as the command file. The test command reaches it as that file, never as an argument.

## Traps

- `run-summary.sh` reads JSON with bash and awk alone: it takes the first `"id":"`, `"model":"` and `"usage":{` after `"message":{` on a `"type":"assistant"` line, and counts a message id once across all counted files (the last line in path byte order wins). An awk array named `sin` prints nothing silently: `sin` is a builtin.
- A script argument the model composes never carries an apostrophe: the close's scripts take ids, verdict words, counts and paths only.
