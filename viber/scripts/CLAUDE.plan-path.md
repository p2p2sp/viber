# viber/scripts - editing the plan path and run branch scripts

What `plan-path.sh` and the library it sources, `run-branch.sh`, decide and print when a plan is started, branched and landed. The skills' `branching*` fragments only act on these answers; the other run scripts stay in `CLAUDE.run-scripts.md`.

## Contracts

- `run-branch.sh` is a library: sourced by `plan-path.sh`, never invoked, mode 100644 in the index, no `set` line of its own. Its functions return 5 with the reason on stderr and HEAD, index and tree untouched; `plan-path.sh` turns that into its own exit 5 (run branch could not be set).
- `plan-path.sh --start` under `allowed` or `required` prints `branch_report`'s lines unchanged and, after them, the decision `branch_decide` and its `decide_*` helpers build in `run-branch.sh` from `st_*` entry rows and `tl_*` tail values: `next:` (`settled`, `kept`, `ask-entry`, `ask-base`, `errors`, `none`, `abort`), `settled:`, `option:` per answer and `note:`, each `option:` carrying the `run:` command to run and the `settle:` value to settle, which the skill's fragment acts on without a per-answer rule; the `plan-path.sh` header lists the rules. A flag value beginning with `--` counts as missing (exit 2). `plan-path.sh --branch` likewise ends its report on the planner decision `branch_plan_decide` and its `plan_*` helpers build from `pb_*` entry rows and its `--work`, `--name` and `--entry` flags: `next:` (`write`, `kept` when the frontmatter's recorded `work:` and `branch:` equal an answer or an ask option, `ask`, `ask-entry`, `errors`, `stop`), `work:`, `branch:`, `show:`, `option:` (with `run:` and `settle:`) and `note:`, which the planner's `branching` fragments only act on; a `--start --settled nothing --entry <key>` call gets that entry's base check.
- `plan-path.sh --land` rewrites the landed copy's `source:` line to the copy's own path and adds `planned: <absolute path of the source plan>` right after it, unless the frontmatter already holds one (a frontmatter with no `source:` gets neither): `run-summary.sh` finds the planning transcripts by that path.
