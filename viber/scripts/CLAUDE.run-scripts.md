# viber/scripts - editing the run scripts' checks and reports

What `plan-index.sh`, `commit-task.sh`, `archive-run.sh`, `red-check.sh`, `run-failures.sh` and `run-tokens.sh` check, read, stage and print. The path and branch scripts (`plan-path.sh`, `run-branch.sh`) and the GitHub wrappers stay in the node.

## Contracts

- `archive-run.sh` takes the run directory as `plan-path.sh` printed its `path:` line minus `/plan.md`, and refuses any path outside `docs/<runs>/`, an absolute one outside the repository or one with a `..` segment. An absolute path inside the repository is folded into its relative form by `cwd_relative()`, copied verbatim into `archive-run.sh`, `plan-index.sh` (the plan) and `commit-task.sh` (the plan, a `--from`/`--first-of` file): the run scripts share no library, so a fix to it changes all three.
- `commit-task.sh` exports `GIT_LITERAL_PATHSPECS=1`: every path it stages is one exact path, never a pattern (bracketed App Router segments). Every `--with` path and extras line is first folded to its repo-relative form (`named_path()`: a relative path's backslash read as `/`, `./` cut), as is a plan `Files:` entry when claimants are compared, so ownership and the `.temp/` refusal see one spelling; `--defer` calls `cwd_relative()` alone, its path byte for byte; the fix-number and `--repair`/`--chore`/... file lists are not. It refuses any `.temp/` path, and derives the `work/` trail paths it stages from the task id or round, never from the caller. A named path whose staged mode differs from HEAD gets that exec bit on disk before `git add -u` (`sync_tree_modes`), so every form commits an index mode change under either `core.fileMode`.
- Extras files: the coder's `<run-dir>/work/<id>-extra.md` and the reviewer's `<id>-extra-review.md`, one path per line (blank lines ignored; a carriage return, surrounding whitespace and a leading `./` stripped; a relative path's backslash read as `/`; an absolute path inside the repository made relative). `plan-index.sh --extra <id>` reads only the coder's, validating the plan as `--split` does, and prints `extra:` (minus a repeat, a `.temp/` path, a path the task's own `Files` lists and one a task not yet done lists) and one `recheck:` per done task owning an extra path; `--split` removes both files of every task not done before printing the index. A plain task commit stages the paths of both files as if on `--with` (same ownership warnings; a path another task's extras file lists is that task's claim, like its `Files:`: refused until it is done), plus the two files and `<id>-options.md`; `--landed` and a fix number ignore them.
- `plan-index.sh` read-after (validate only, skipped under `--split` and on a plain call with `status.md` beside the plan, a landed run): exit 4 when a task's `Verification` (the part after ` -> ` included) or `DoD` names, as a whole path token, a file a lower-numbered task lists with no dependency path to it; a file the reader lists itself is skipped.
- `plan-index.sh` Uses check (same exemptions): exit 4 when a task's `DoD` or `Delivers` names an appendix block id as a whole token outside backtick spans that its `Uses` does not name.
- `plan-index.sh` Verification checks (same exemptions, `--extra` included; both read the part before the first ` -> `): exit 4 when a task's `Files` writes under an integration test directory (the shallowest segment that is `integration` or holds `integration[-_.]?tests?`, case folded; for a `.integration.` file name the file itself) and no command that is no `grep`, `git grep` or `rg` names that file, a directory of it at or below the test directory, or a file directly inside such a directory; and when a `git grep` without the literal `--untracked` token names a `Files` path the tree does not hold. The git grep check cuts commands at `&&`, `||`, `;` and `|` only (a comma can sit in a pattern), the integration check also at `,`.
- `commit-task.sh --drop <plan> <path>...` deletes only an untracked, unignored file outside the run directory that no task's `Files` and no extras file lists; any other path is kept with a `warning: kept <path> - <reason>` stderr line and the call goes on, exit 0. It commits nothing and leaves the index and `status.md` alone.
- `commit-task.sh --rule <subject> --from <ruling-file>` and `--decide <id> --from <ruling-file>` read the arbiter's ruling file, which must lie under `<run-dir>/work/` with its `RULING:`, `WHY:` and `COST:` lines non-empty (else nothing is recorded and the file stays); `--decide` records `auto: <ruling>`, or with `--first-of <options-file>` the first option of the file's latest `DECIDE:` line. Any form taking a plan stages `work/ruling-*.md` with the register.
- `red-check.sh "<plan>" "<id>"` prints one `red-check:` line (`FAIL-AS-EXPECTED <log>`, `PASSED-WITHOUT-CHANGE <files>`, `UNRUNNABLE <reason>`) with exit 0, exit 2 on bad arguments or plan. A linked directory (`node_modules`) is a real directory of one link per entry, an `@scope` directory likewise, never one link to the whole; an entry linking into a workspace package of the repository points at the worktree's own copy, so the red run loads HEAD's package code. Each directory holding links is listed in `red-check.owner` before it is made; the trap and the next run's recovery unlink every link entry of a listed directory first, then `git worktree remove --force` and `git worktree prune`, so the forced remove never reaches the main tree through a link.
- `run-failures.sh --lessons <run-dir>` writes nothing and prints one `lessons: <Name> x<n>, ...` line (most often first, then by name) or `lessons: none`, which `implementor` turns into the `run-lessons:` coder line. It reads only the first line of each Blocking item of `review-*.md` (not `final-review-*` or `tests-*`), counts each test-strategy `` `<Name>` `` once per line, dedupes a finding repeated across rounds of one task like the failure trail, and needs no `status.md` in the run directory.
- `run-tokens.sh <run-dir>` exits 0 with its `tokens:` lines or the one `tokens: unavailable - <reason>` line, 2 only on an unusable argument. It counts a transcript whose first line names `<runs>/<key>` followed by `/`, a backslash, a double quote or a space, from Claude Code's undocumented `subagents/agent-<id>.jsonl` layout, so a layout change reads as `unavailable`, never as an error. It never counts the `closeout` role nor a `<synthetic>` model line (an API error record), opens no transcript last written before the day the run key names, and turns the whole report `unavailable` when one counted transcript cannot be read through.
- `run-tokens.sh` ends either form on one `rounds: plan review <n>` or `rounds: plan review unavailable - <reason>` line: `<n>` counts the `planner-review` and `planner-graph-review` transcripts, whenever written, whose first line names the `planned:` path of the run's `plan.md`; each dispatch counts once, a retry too, so the count is an upper bound. A run landed before `plan-path.sh` wrote that line reads `unavailable`.

## Change together

- The `Covers:` token grammar (`covnums`) and the `;` cut of a `DoD` line outside backtick spans (`dodcut`) each live in two copies in `plan-index.sh`, validate and split: one edit changes both.

## Traps

- `run-tokens.sh` reads JSON with bash and awk alone: it takes the first `"id":"`, `"model":"` and `"usage":{` after `"message":{` on a `"type":"assistant"` line, and counts a message id once across all counted files (the last line in path byte order wins). An awk array named `sin` prints nothing silently: `sin` is a builtin.
- `plan-index.sh` counts only `AC<n>` tokens of `Covers:`; `#<n>` and a bare `<n>` cover nothing (exit 4).
