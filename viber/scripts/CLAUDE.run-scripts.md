# viber/scripts - editing the run scripts' checks and reports

What `plan-index.sh`, `commit-task.sh`, `archive-run.sh` and `run-failures.sh` check, read, stage and print. The task step, the scheduling and the red check are in `CLAUDE.task-step.md`, the path and branch scripts in `CLAUDE.plan-path.md`, the close scripts in `CLAUDE.close-scripts.md`.

## Contracts

- `archive-run.sh` takes the run directory as `plan-path.sh` printed its `path:` line minus `/plan.md`, and refuses any path outside `docs/<runs>/`, an absolute one outside the repository or one with a `..` segment. An absolute path inside the repository is folded into its relative form by `rootRelative` of `lib/root-relative.ts` (also the plan and the extras lines of `plan-index.sh`), as `cwd_relative()` does in `commit-task.sh` (the plan, a `--from`/`--first-of` file): a fix to one goes to the other.
- `archive-run.sh` scratch (`clearScratch` of `lib/archive-run.ts`, the list in the entry header), removed under `.temp/viber/` best effort and silently once the run is archived: each task directory the plan names, `lessons`, `waits`, `guard`, `test-runner`, `final-fix`, `repair-*`, `extension-*`, `intent/summary-*.md`, `fixer/tree-record` and, under `planner/`, every `.md` file and the state file `plan-build`.
- `commit-task.sh` exports `GIT_LITERAL_PATHSPECS=1`: every path it stages is one exact path, never a pattern (bracketed App Router segments). Every `--with` path and extras line is first folded to its repo-relative form (`named_path()`: a relative path's backslash read as `/`, `./` cut), as is a plan `Files:` entry when claimants are compared, so ownership and the `.temp/` refusal see one spelling; `--defer` calls `cwd_relative()` alone, its path byte for byte; the fix-number and `--chore`/... file lists are not. It refuses any `.temp/` path, and derives the `work/` trail paths it stages from the task id or round, never from the caller. A named path whose staged mode differs from HEAD gets that exec bit on disk before `git add -u` (`sync_tree_modes`), so every form commits an index mode change under either `core.fileMode`.
- Extras files: the coder's `<run-dir>/work/<id>-extra.md` and the reviewer's `<id>-extra-review.md`, one path per line (blank lines ignored; a carriage return, surrounding whitespace and a leading `./` stripped; a relative path's backslash read as `/`; an absolute path inside the repository made relative). `plan-index.sh --extra <id>` reads only the coder's, validating the plan as `--split` does, and prints `extra:` (minus a repeat, a `.temp/` path, a path the task's own `Files` lists and one a task neither done nor skipped lists) and one `recheck:` per done task owning an extra path; `--split` removes both files of every task not done before printing the index. A plain task commit stages the paths of both files as if on `--with` (same ownership warnings; a path another task's extras file lists is that task's claim, like its `Files:`: refused until it is done), plus the two files and `<id>-options.md`; `--landed` and a fix number ignore them.
- `plan-index.sh` read-after (validate only, skipped under `--split` and on a plain call with `status.md` beside the plan, a landed run): exit 4 when a task's `Verification` (the part after ` -> ` included), `Delivers` or `DoD` names, as a whole path token, a file a lower-numbered task lists with no dependency path to it (a file the reader lists itself is skipped; the `Delivers` of a task whose every `Files` path is under `docs/adr/` is not read), and, in the forward case, when it names a file the tree does not hold (checked from the script's cwd, so the repository root) that only a higher-numbered task lists: a file the tree already holds is today's file, never a forward reference.
- `plan-index.sh` fresh-plan checks (skipped under `--split`, `--extra` and on a landed plan; exit 4, each defect a `FIX:` line naming its fix and the rule of `references/plan-rules-script.md`): task ids not `T1`, `T2`, ... and contract ids not `C1`, `C2`, ... in order; a task title opening with a commit type prefix (printed as written); a `Verification` wrapped in backticks, running inline interpreter code (`node --no-warnings -e` counts, each command cut at `;`, `|`, `||`, `&&` outside quotes) or a script under `.temp/`; a `CLAUDE.md` (last path segment) in `Files` while `build.memory` is on, resolved from the caller's cwd; an `attachments:` name that is invalid, repeated (case folded) or missing for the `DoD` that names it (only when the frontmatter holds the key; every bad entry is reported); and a template slot (a `<...>` span of `spec-full.md`, `spec-lite.md` or `tasks.md` under `../skills/planner/templates`) left in the text outside fences, HTML comments, backtick spans, the `## Open items` section and the `## Contracts` appendix, the scan running before the heading and title rules; a `###` heading under `## Behaviour` other than `### Edge cases` or `### S<k> - <title>` in order (a stray heading takes a place in the count); and a `- modify - <path>` or `- delete - <path>` line of `### File map` (outside a fence, paths cut at the first ` - `, split on commas) whose path the tree, read from the cwd, does not hold.
- `plan-index.sh` defects: every one is a stderr line opening on `FIX:`, or on `SPLIT:` for a task past its `Files` or `DoD` cap, exit 3 or 4 with nothing on stdout, and one run prints them all: no check is skipped for an earlier defect, and a malformed task heading is reported alone (`broken` of `lib/plan-index/read.ts` skips every later check of its block, which still records its `Covers` and `Uses` so nothing reads as unused). Usage errors, a missing plan or input file and an unknown id of `--extra`, `--dispatch` or `--slice` stay `error:` lines, exit 2. `commit-task.sh --leftovers` reads the first `FIX:`, `SPLIT:` or `error:` line.
- `plan-index.sh <plan> --input <summary file>` (validate only, exit 2 beside any other mode or on a missing file) adds, whatever `status.md` holds, three `FIX:` checks read from the file's line-start `Attachment:`, `Root cause:` and `Repro:` lines: an attachment path no `attachments:` entry value holds exactly (no slash normalisation); a `## Root cause` heading outside a fence missing while the file has a `Root cause:` line (any value) or an `Attachment:` under `.temp/viber/code-auditor/`, or present while it has neither; a `Repro:` path no task `Repro:` line holds.
- `plan-index.sh` threshold line (fresh plan only, last on stdout): `threshold: <n> tasks, past 30` past 30 tasks and past `--accepted <n>` (validate mode only, the count the user kept; never beside `--split`, `--extra`, `--dispatch`, `--slice` or `--final-review`, exit 2). The index names no reviewer.
- `plan-index.sh` open items (every mode, a fresh and a landed plan; exit 4, each defect a `FIX:` line ending `(Open items)`): a line of `## Open items` that is not `- critical|note | <task id>|plan | <text>`, an id naming no task of the plan, a task holding more than 3 notes. `--split` cuts the section out of `spec.md`, as it cuts `## Phases` into `phases.md`, and ends `tasks/<id>.md` on `## Notes` with one `- N<k>: <text>` line per `note` item of that task, numbered from 1 in section order; a task with no note gets no heading, and a `critical` item or a `plan` note reaches no task file.
- The checks of a fresh plan and of `--input` are also what `skills/planner/scripts/plan-build.sh` runs in process over a plan text before it writes it (`planDefects` of `lib/plan-index/run.ts`), so a `FIX:` line reworded here is reworded for the planner too.
- `plan-index.sh <plan> --dispatch <id> coder|reviewer` validates as `--split` does and prints, instead of the index, the labelled lines of that task's dispatch, each omitted when empty: `prior:` names the task's own dependencies only, `decision:` one line per `status.md` decision of the task or any dependency, direct or transitive, `deferred:` the task's entries, `run-lessons:` (coder only) the second line of `.temp/viber/lessons`, `baseline:` only under `build.baseline-tests` `fast` or `full`; `<plugin root>` is the absolute path the entry was started by minus `/scripts/<name>.ts`, backslashes read as `/`. An unknown id or form, or `--split`/`--extra` beside it, exits 2.
- `plan-index.sh` Uses check (same exemptions): exit 4 when a task's `DoD` or `Delivers` names an appendix block id as a whole token outside backtick spans that its `Uses` does not name.
- `plan-index.sh` Verification checks (same exemptions, `--extra` included; both read the part before the first ` -> `): exit 4 when a task's `Files` writes under an integration test directory (the shallowest segment that is `integration` or holds `integration[-_.]?tests?`, case folded; for a `.integration.` file name the file itself) and no command that is no `grep`, `git grep` or `rg` names that file, a directory of it at or below the test directory, or a file directly inside such a directory; and when a `git grep` without the literal `--untracked` token names a `Files` path the tree does not hold. The git grep check cuts commands at `&&`, `||`, `;` and `|` only (a comma can sit in a pattern), the integration check also at `,`.
- `commit-task.sh --drop <plan> <path>...` deletes only an untracked, unignored file outside the run directory that no task's `Files` and no extras file lists; any other path is kept with a `warning: kept <path> - <reason>` stderr line and the call goes on, exit 0. It commits nothing and leaves the index and `status.md` alone.
- `commit-task.sh --rule <subject> --from <ruling-file>` and `--decide <id> --from <ruling-file>` read the arbiter's ruling file, which must lie under `<run-dir>/work/` with its `RULING:`, `WHY:` and `COST:` lines non-empty (else nothing is recorded and the file stays); `--decide` records `auto: <ruling>`, or with `--first-of <options-file>` the first option of the file's first `DECIDE:` line, or with a `<text>` argument that one line verbatim (`sequenced after <other>: both need <path>` from `task-step.sh`), the same id and text twice leaving one `decision:` line. Any form taking a plan stages `work/ruling-*.md` with the register.
- A task commit records every `--with` or extras path it refuses with `warning: refused <path> - claimed by task <id>` as a `<task id>:<path>` entry of the `refused:` key of `status.md` (a space, tab or `%` of the path as `%20`, `%09`, `%25`), in the same commit. The key is written only by the first such refusal of a run, as the last line the file then holds, so a run with no refusal keeps the `status.md` it had; `lib/run-notes.ts` reads them back.
- `plan-index.sh` is the wrapper of `plan-index.ts` beside it (core in `../lib/plan-index/`): a test that copies the scripts needs the entry and `viber/lib/` beside the wrapper. Its `--split` commits through a private index (`GitWrite.commit`).
- `run-failures.sh` is the wrapper of `run-failures.ts` beside it (core in `../lib/run-failures.ts`): `task-step.sh` and a test that copies the scripts need the entry and `viber/lib/` beside the wrapper.
- `run-failures.sh --lessons <run-dir>` writes nothing and prints one `lessons: <Name> x<n>, ...` line (most often first, then by name) or `lessons: none`, which `task-step.sh` stores as the session lessons list `plan-index.sh --dispatch` prints as `run-lessons:`, and the close's fix and repair coders take from their own call. It reads only the first line of each Blocking item of `review-*.md` (not `final-review-*` or `tests-*`), counts each test-strategy `` `<Name>` `` once per line, dedupes a finding repeated across rounds of one task like the failure trail, and needs no `status.md` in the run directory.

## Change together

- The issue footer of a run commit: `issueOf` of `lib/plan-index/split.ts` and `issue_ref()` of `commit-task.sh`.

## Traps

- `plan-index.sh` counts only `AC<n>` tokens of `Covers:`; `#<n>` and a bare `<n>` cover nothing (exit 4).
