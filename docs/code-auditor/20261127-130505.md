### 5 - viber/skills/spec-implementor/scripts/lib/build-tasks.ts:180 - A call killed during a task's commit leaves the task done with no commit, for good
Hunt: race-state
Defect: The task is written to state.json as `done` with no awaited dispatch before git has made its commit, so a call that dies while the commit (its hooks) runs loses the commit and nothing ever makes it again.
Proof:
- Shared state: `work/state.json` and the repository's HEAD.
- `build-tasks.ts:180-184`: `run.state = "done";` / `run.open = null;` / ... / `const done = commitRun(ctx, `T${task.num} - ${task.title}`, paths, ...)`. `viber/skills/spec-implementor/scripts/lib/build-state.ts:170-175`: `save(ctx);` ... `return ctx.git.commit(ctx.root, message, [...paths, ...RUN_FILES.map((file) => `${dir}/${file}`), ...mine]);`. The state reaches the disk first, then the commit runs with the project's hooks (`build-run.ts:18`: `a commit whose hooks run the linter holds the lock for a while`).
- Interleaving: the reviewer of T3 returns PASS, the call saves T3 as `done`, starts `git commit`, and the process is killed while a hook runs (the Bash tool's timeout on a slow hook, a user interrupt). HEAD has no `T3 - <title>` commit; state.json says `done`, `open: null`.
- No path repairs it. The repeated call is dropped: `build-tasks.ts:247`: `if (task === undefined || runOf(ctx, num).open !== id) return;`. A resume keeps it: `build-run.ts:132`: `tasks[String(task.num)] = before?.state === "done" ? { ...before, after } : freshTask(after, before?.seq ?? 0);`, and `build-run.ts:140-141` only looks its sha up in the log, `?? null` when there is none. No line checks that a done task without `no-change` has a commit.
- Output: the outcome reads `T3 - <title>: done`, every later task and the final review (`git diff --name-status <base> HEAD`, `adapters/git.ts:91`) run without T3's work in HEAD, and the files only surface in the END line `Left uncommitted:`.
- Expected: `viber/skills/spec-implementor/scripts/build.ts:83-86`: `One commit a task, `T<n> - <title>`, of its `Files` and the paths its coder reported, none when they hold no change`, and `build.ts:21-22`: `a task that is done stays done`, which holds only when done means committed.
Fix: On `start` (and on an event finding a done task with `sha: null` and no `no-change` mark), treat a done task whose commit subject is absent from `git log <base>..HEAD` and whose paths are still dirty as not done and commit or restart it.

### 4 - viber/skills/commit/scripts/lib/commit-args.ts:63 - commit.sh reads the resolved path of commit-context again from the cwd and can commit another file
Hunt: contract-mismatch
Defect: commit-context prints root-relative paths in the RUN line, and commit.sh resolves that same text once more with the cwd prefix first, so in a subdirectory holding a nested directory of its own name the commit takes a different file than the one the message was written from.
Proof:
- Producer: `viber/skills/commit/scripts/lib/commit-context.ts:33`: `const { root, mode, paths, missing, refs } = readSelector(argv[0] ?? "", cwd, ports);`, `:36`: `const label = paths.join(" ");`, `:43`: `` `RUN: "${rootAbove(script, 3)}/skills/commit/scripts/commit.sh" "<message>"${named ? ` '${label}'` : ""}\n` ``. `paths` are already root-relative (`commit-args.ts:63`: `if (prefix !== "" && held(prefix + path)) return prefix + path;`).
- Consumer: `viber/skills/commit/scripts/lib/commit.ts:66`: `const { root, mode, paths, missing } = readSelector(argv.slice(1).join(" "), cwd, ports);`, which runs `commit-args.ts:71-72`: `const whole = resolve(raw);` / `if (whole !== null) return answer("paths", [whole]);` and so applies line 63 a second time before line 64 (`return held(path) ? path : null;`). No caller strips or marks the label as resolved.
- Input: repository with `app/config.json` (changed) and `app/app/config.json`, cwd `app`, `/commit config.json`. commit-context resolves `config.json` to `app/config.json`, shows its diff and prints `'app/config.json'`. commit.sh resolves `app/config.json` from cwd `app`: `held("app/" + "app/config.json")` is true, so it stages and commits `app/app/config.json` (or prints `Nothing to commit` when that file is unchanged) under a message describing `app/config.json`.
- Expected: `commit-args.ts:2-4`: `shared by commit-context (which measures the selected set) and commit (which stages it), so the two never read one selector two ways`.
Fix: Have commit.sh take the label as root-relative (try the path from the root before the cwd prefix, or pass the paths through a flag that skips the prefix step).
