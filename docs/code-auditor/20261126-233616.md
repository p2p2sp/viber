### 5 - viber/skills/implementor/scripts/lib/build-tasks.ts:31 - A glob task commits the new file of another task still in flight
Hunt: race-state
Defect: A task's glob is resolved against the tree at start to order the tasks, and again at diff and commit time to pick its paths, so a file another unfinished task creates in between lands in the glob task's diff and commit.
Proof: Input: T1 `Files: +src/new.ts`, T2 `Files: src/**/*.ts`, both `Blocked-by: none`. Order is derived once, at start, from the tree as it is then: `const order = orderOf(plan.tasks, ctx.files());` (build-run.ts:114); a glob owns only files the tree holds: `for (const file of tree) if (pattern.test(file)) owned.add(file);` (plan-order.ts:57), and a task follows another only on `if (theirs.has(file)) {` (plan-order.ts:107). `src/new.ts` is not in the tree yet, so neither task runs after the other and both coders start. No check stops the plan: the glob only has to match one file (`if (!tree.some((file) => pattern.test(file))) say(...)`, plan-check.ts:82) and the `+` path only has to be absent (`if (held.has(entry.path)) say(...)`, plan-check.ts:84). Shared state: the work tree file `src/new.ts`. Interleaving: T1's coder writes it; T2's coder returns DONE first; that call resolves the glob again, `return [...new Set([...ownedFiles(task, ctx.files()), ...runOf(ctx, task.num).extra])];` (build-tasks.ts:31), over a list that holds untracked files (`git(root, ["ls-files", "-z", "--cached", "--others", "--exclude-standard"])`, planner/scripts/lib/adapters/tree.ts:25). T2's reviewer is handed T1's half-written file (`ctx.git.diff(ctx.root, taskPaths(ctx, task))`, build-tasks.ts:201) and `commitRun(ctx, \`T${task.num} - ${task.title}\`, paths)` (build-tasks.ts:179) commits it under T2; T1 then ends `no-change` or held with its file already in history. Expected, from the header of build.ts: "one commit a task, `T<n> - <title>`, of its `Files`" (build.ts:60) and "a `FILES` path in the `Files` of another unfinished task is noted as `conflict` and left out of the commit" (build.ts:119-120): a file of an unfinished task never enters another task's commit.
Fix: In `orderOf`, also test each literal `Files` path of one task against the glob patterns of the other, so a glob task and a task creating a file the glob matches never run at once.

### 4 - viber/skills/implementor/scripts/lib/adapters/git.ts:90 - A changed path with a non-ASCII character reaches changes.md quoted and matches no rule glob
Hunt: wrong-result
Defect: `changes` reads `git diff --name-status` without `-z`, so git prints a path holding a non-ASCII byte C-quoted with octal escapes, and that text is matched against the rule globs and handed to the close agents as the path.
Proof: Input: the build changed only `docs/przegląd.md`, and `.claude/rules/docs.md` holds `paths:` with `- "docs/**"`. `return git(root, ["diff", "--name-status", base, "HEAD"]).out.trim();` (git.ts:90) gives, under git's default `core.quotePath`, the line `M<tab>"docs/przegl\304\205d.md"`. Every other path list in the adapter asks for `-z` (`["status", "--porcelain", "-z", ...]`, git.ts:66; `["ls-files", "-z", "--", path]`, git.ts:43); this one does not. The only reader that parses it: `const changed = changes.split("\n").flatMap((line) => line.split("\t").slice(1)).filter((path) => path !== "");` (build-rules.ts:38), then `return changed.some((file) => pattern.test(file));` (build-rules.ts:47): `^docs/.*$` fails on the leading `"`. So `if (!retry && matchingRules(ctx, listed).length === 0) return enter(ctx, "extensions");` (build-close.ts:158) skips the rules writer, and `ctx.fs.writeText(\`${ctx.work}/changes.md\`, \`${list}\n\`);` (build-close.ts:40) hands the escaped name to the final reviewer, memory writer and repair coder. Expected: ports.ts:43 "`git diff --name-status <base> HEAD`: one `<status>\t<path>` line per file", and spec R10 (docs/specs/2026-11-26-22-08-39_build-memory-rules/spec.md:22) "The step dispatches `viber:rules-writer` only when the `paths:` globs of at least one rule file under `.claude/rules/` match a file of `changes.md`."
Fix: Run the diff with `-c core.quotePath=false` (or `-z` and rebuild the `<status>\t<path>` lines) so each path is the literal one.

### 4 - viber/skills/implementor/scripts/lib/build-close.ts:122 - A failed `git diff` from base is read as a build that changed nothing
Hunt: silent-failure
Defect: The exit status of the diff from `base` is dropped, so when git cannot resolve `base` the empty output skips the final review, the memory step and the rules step with no note.
Proof: Input: a held run resumed in a clone that lacks the base commit (a shallow clone), the case build.ts:72-74 promises ("is committed as it stands (`run state`), so `start` resumes it on any machine"). `git diff --name-status <base> HEAD` exits 128 with nothing on stdout. "" };` (adapters/git.ts:20), and `changes` discards it: `return git(root, ["diff", "--name-status", base, "HEAD"]).out.trim();` (adapters/git.ts:90). Callers, none checking: `if (changes(ctx) === "") return enter(ctx, "tests");` (build-close.ts:122), `if (!retry && listed === "") return enter(ctx, "rules");` (build-close.ts:143), `if (!retry && matchingRules(ctx, listed).length === 0) return enter(ctx, "extensions");` (build-close.ts:158). ### 4 - viber/skills/implementor/scripts/lib/build-rules.ts:28 - A `paths:` list written without indentation gives no glob

### 4 - viber/skills/ui-designer/scripts/check_contrast.ts:251 - Run through a symlinked path the contrast check prints nothing and exits 0
Hunt: silent-failure
Defect: The entry guard compares the unresolved `process.argv[1]` with `import.meta.url`, which Node gives with symlinks resolved for the main module, so under a plugin directory reached through a symlink `main` never runs.
Proof: Input: the plugin installed under a path with a symlinked component (for example a `~/.claude` that links into a dotfiles repository), and the call the skill prescribes, `<resolved node cmd> "${CLAUDE_SKILL_DIR}/scripts/check_contrast.ts" FG BG [TYPE] ...` (ui-designer/SKILL.md:87), with `"#777" "#fff"` (4.48:1, under 4.5). `if (process.argv[1] && resolve(process.argv[1]) === fileURLToPath(import.meta.url)) {` (check_contrast.ts:251): `resolve` keeps the link in the path, `import.meta.url` names the real file, the two differ, and `process.exitCode = main(process.argv.slice(2));` (check_contrast.ts:252) is skipped: no line on stdout, exit 0. Expected, check_contrast.ts:16: "Exit 1 if any pair fails the AA threshold FOR ITS OWN TYPE".
