### T7 - Count the plan review rounds in the token report
- TDD: required
- Covers: AC6
- Uses: C5, C6
- Depends-on: T6
- Files: viber/scripts/run-tokens.sh, tests/viber/run-tokens.test.ts
- Delivers: `run-tokens.sh` printing the C5 rounds line after its token lines, read from the C6 `planned:` line
- Verification: node --test tests/viber/run-tokens.test.ts tests/portability.unit.test.ts -> every case passes
- DoD.1: a run whose `plan.md` names `planned: C:/plans/p.md`, with three transcripts of an agent type ending in `:planner-review` and one ending in `:planner-graph-review` whose first line names that path, the backslash form included, prints `rounds: plan review 4`, a review transcript last written before the day of the run key counting too, and every such transcript counting once, a retried dispatch included
- DoD.2: transcripts of other agent types or naming another path do not count
- DoD.3: a `plan.md` with no `planned:` line prints `rounds: plan review unavailable - no planned line in plan.md`
- DoD.4: no matching transcript prints `rounds: plan review unavailable - no review transcript names the plan`
- DoD.5: each `tokens: unavailable - <reason>` line, for every one of its three reasons, is followed by the rounds line, `rounds: plan review unavailable - no projects directory` when the projects directory is missing
- DoD.6: the token lines stay byte for byte as today

## Goal
Plans should pass their review in fewer rounds and builds should waste fewer coder attempts. The planner sees the code its change reaches, `plan-index.sh` rejects two mechanical plan mistakes, coders learn the test rules earlier tasks of the same run broke, a reviewer flags a whole class of a test-rule breach at once, a coder stalled on a contradiction gets the arbiter's ruling and continues, and the archive records the numbers that show whether it worked.

## Covered criteria
6. The final summary, and so `outcome.md`, carries the plan review rounds, the attempts of every task needing more than one, and the number of rulings.

## Must not change
- The `- Blocking [<cause>] <path>:<line> - <what is wrong>` item line and its four causes, and the `failures.md` trail and its `failures:` line.
- `hooks/scripts/plan-gate.sh` and the rule that every review-set member passes after the last plan write.
- The repair pass: a `DECIDE:` there is never sent to the arbiter, and a failed repair pass goes to `case: cap`.
- The 5-attempt limit, the tier climb per attempt, and attempt 5 holding the task without an arbiter.

## Out of scope

- Splitting the planner into subagents and a separate test reviewer.
- A coder starting the arbiter itself in the background (a separate experiment first).
- `final-reviewer.md` rule spelling and the repair pass's `DECIDE:` handling.
- `CLAUDE.md` nodes naming the changed behaviour: the build's memory close updates them.
