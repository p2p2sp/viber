- Delivers: the `build.extensions` and `build.extensions-missing` lines of the block
- Verification: node --test tests/viber/config/extensions.unit.test.ts -> every case passes
- DoD.1: an entry of the `extensions:` map under `build:` whose name matches `^[a-z0-9][a-z0-9-]*$` and whose agent file exists under `.claude/agents/` of the repository is found, and every other name is missing
- DoD.2: consecutive found entries marked `parallel: true` in any letter case join into one step with ` + `, a found entry not marked parallel is a step alone, and the first `parallel` of an entry wins
- DoD.3: missing names are dropped before the steps are grouped and listed on `build.extensions-missing` in listed order, each line reading `none` when it has no name
- DoD.4: the map ends at the first line that is neither blank nor a comment and is indented no deeper than its key, a value after the key other than a comment gives no entry, the first key line of the map sets the entry depth, a deeper key line is an option of the entry above, a shallower one is ignored and an entry's inline value is ignored
- DoD.5: a name counts once, at its first entry with that entry's option, and a map outside `build:` gives no name
- DoD.6: a line of the map is never read as a child of `build:`, so an entry named like a switch changes no switch

Lay the ground the rest of the test rewrite stands on: a Node core tested in process, a deterministic lint job, one CI workflow whose test step fits in a minute, and the first script (`config.sh`) ported to it. The suite is written from scratch: no old test runs beside a new one as an oracle.
