## Goal
A build still writes unit and component tests for trivial cases, because the `Earned` rule of `viber/references/test-strategy.md` is a list of banned tests that never says what counts as a decision in the logic, so a case missing from the list earns a test. The rule gains a gate a coder answers before writing a test and a criterion for plain code, and names what a static check of the stack already rejects, so the rule covers the unlisted case. The planner, the coder, the reviewers and the code auditor all read this one rule, so the wording changes in one place. A build also runs its build and tests twice at its end, because `final-reviewer` proves its findings by running them just before the final test run does the same, so the final reviewer stops running anything and judges by reading.

## Contracts

### C1 - Earned rule

File: viber/references/test-strategy.md

```
- Earned: A test exists only for a critical path or a decision in the logic: name the bug it would catch; none, or only a deliberate change (a constant, default or name), means no test. Plain code earns one only where it validates, normalises, derives, enforces or has a side effect, an edge case only where it flips a decision's outcome, never as a null, empty or missing input. Never tested: what the compiler, type checker, linter or schema rejects, framework or third-party library behaviour, an assertion true by construction, the shape of data, a count of fields, members or entries, a type's visibility or modifiers, an export, a registration, what a user interface renders (markup, element order, static text, styling). A test that fails on a refactor keeping the observed behaviour is a finding. (blocking)
```
