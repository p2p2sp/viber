# tests/viber - viber's script, hook and shipped-content suite

One test per viber script, hook script or `.ts` module, named after it (the pair `<name>.test.ts` and `<name>.critical.test.ts` with their `<name>-fixture.ts`, as `tests/CLAUDE.md` defines it; a file name below means the pair), plus the checks that bind shipped markdown, templates and `hooks.json` to what the scripts and `plugin.json` carry. The helpers it imports belong to `tests/harness/`; no other plugin is tested here.

## Relationships

- SUTs: `viber/lib/` and the entries `tests/CLAUDE.md` lists (`viber/scripts/*.ts`, the skill entries, the hook entry `file-guard.ts`) in process (`config/<module>.unit.test.ts` per config module, `lib/<module>.unit.test.ts` per other core module, `lib/plan-index/<module>.unit.test.ts` per module of the plan-index core, `lib/` also for the fakes and the adapters), `viber/scripts/`, `viber/skills/*/scripts/` (including `pro-designer`'s `check_contrast.ts` and `check_node.sh`, whose contracts live in that skill's node), `viber/hooks/scripts/`, `viber/hooks/write/report-name.ts`, and the lens files of `viber/skills/code-auditor/references/lenses/` (their shape, and the signals rules of a single-quoted `<scope>` and no `\b`, by `lenses.unit.test.ts`, the map-signal commands of their `<lens>.signals.md` files by `lens-map-signals.test.ts`).
- `viber/scripts/run-branch.sh` and `viber/hooks/register.tsx` have no test file.

## Contracts

- The shell follows the SUT's shebang: a `#!/bin/sh` script runs through `forEachShell("posix", ...)`, a `#!/usr/bin/env bash` one through `forEachShell("bash", ...)` or a plain `runScript`.
- Hook scripts run with `shell: "bash"`, the way `hooks.json` invokes them (`bash "${CLAUDE_PLUGIN_ROOT}/hooks/scripts/<name>.sh"`): the test proves the content, never the exec bit.
- Hook payloads and transcript fixtures are JS objects serialized with `JSON.stringify`, never hand-escaped: the scripts read raw text with grep/sed/awk and unescape it themselves, so a hand-escaped fixture proves the wrong thing.
- The critical files of the guard hooks `kill-guard` and `shell-guard` carry whole deny and allow tables: a gate is proven on Linux and on Windows against that system's own grep, sed and awk. Elsewhere a critical file takes single cases and short tables.
- A case naming a drive-letter, backslash or MSYS spelling of a path is critical wherever it sits, since only the Windows leg runs it.
- `config/<module>.unit.test.ts` call the config core entry (`runConfig`) alone, over `fakeFs` and `fakeGit`; `config.critical.test.ts` is the one legacy file of the config: it runs the wrapper `config.sh` as a process, with and without Node. The `lib/<name>.unit.test.ts` file of every core a wrapper script runs calls the core entry of its name the same way (`fakeClock` for the stamp of `summary-path`, `handoff-path` and `plan-build` and the ids of `frame`, `rules-map` and `memory-map`); `<name>.critical.test.ts` is the one legacy file of each, running the wrapper as a process. Four have none: `plan-build`; `run-notes` and `task-ready`, whose wrappers run only inside the legacy tests of their callers `commit-task.sh`, `run-summary.sh` and `task-step.sh`; and `file-guard`, whose wrapper no test spawns (`guard-prose.unit.test.ts` reads its text). `lib/abs-path.unit.test.ts`, `lib/stamp.unit.test.ts`, `lib/byte-order.unit.test.ts`, `lib/repo-prefix.unit.test.ts`, `lib/plugin-root.unit.test.ts`, `lib/run-header.unit.test.ts`, `lib/hunt-brief.unit.test.ts`, `lib/map-answer.unit.test.ts`, `lib/commit-args.unit.test.ts`, `lib/drive-path.unit.test.ts` and `lib/root-relative.unit.test.ts` call the helper of their name, `lib/reach.unit.test.ts`, `lib/plan-text.unit.test.ts` and `lib/plan-graph.unit.test.ts` the three modules that serve the `plan-build` core (`collectReach`; `parsePlan`, `slicesOf`, `openItemsOf` and the cuts of a frame and an author file; `orderTasks` and `arrangeTasks`). The files of `lib/plan-index/` call `runPlanIndex` through `indexOf` of `lib/plan-index/scene.ts` (`text` and `slotsOf` of `read` alone are called direct), over the plan texts `plan-body.ts` builds; a check of a fresh plan is one row of `FRESH` in `check.unit.test.ts`, which proves the defect on a fresh plan and its absence on a landed one. The cores of `run-changes`, `tree-record`, `diff-files`, `rules-map` and `memory-map` are given what git answers as the tables of a `fakeGit` repository; what git itself answers is held by the contract cases of the port. The cores of `commit`, `archive-run`, `worktree` and `plan-index` (`--split`) write through a `fakeRepository`, whose commits and index the case reads. `collectReach` and the core of `plan-build` are given the text files of a `fakeGit` repository (`texts`), which the fake searches itself. The core of `frame` is given lens files planted in the `fakeFs`; the six shipped lens names and the `Worktree: none` of `design` alone are held by `lenses.unit.test.ts`. The cases on the header of the `run-failures.ts` entry sit in `failure-trail-prose.unit.test.ts`, those on the header of `rules-map.ts` in `rules-trail-prose.unit.test.ts`; the exec bit and the line endings of a wrapper are held by the `invocations` and `script-portability` lint rules, not by a test. `close-part.unit.test.ts` reads the shipped `implementor` close part and its fragments from the tree, plants them in a `fakeFs` and calls `runSkillPart`: a `lib/` unit file reads no file, so the cases on shipped text sit beside it. `session-start.critical.test.ts` and its fixture stage an absent or old `node` for the hook's Node check through `shellUtilsPath()`, as `merge-settings.critical.test.ts` does for what `merge-settings.sh` keeps without it.
- The report-name module exports pure functions, imported directly by its `*.unit.test.ts` file.
- `code-auditor.unit.test.ts` holds every `viber:<name>` `code-auditor/SKILL.md` dispatches to a file listed in `plugin.json` `agents[]`, and every tracked file outside `docs/` and the `CLAUDE.md` nodes to naming no retired script, agent or reference: retiring one adds its token to `FORBIDDEN`.
- `ui-tells.unit.test.ts` holds `viber/references/ui-tells.md` to at most 4096 bytes, the `##` sections of `pro-designer`'s `anti-slop.md`, no phrase written for pro-designer's context and no dash character, and `task-coder` and `task-reviewer` to reading it and naming `anti-slop` nowhere.
- The twenty-eight `*-prose.unit.test.ts` files read shipped markdown and scripts as text; the file each one binds is in `CLAUDE.prose-tests.md`.
- `planner-blocks.unit.test.ts` reads the four planning agents (`plan-surveyor`, `plan-architect`, `plan-author`, `plan-judge`) from the tree and calls `runPlanBuild` on fakes: the `## Input` of each names exactly the lines of the fullest block the core prints for it and describes the text of every `add:` field. A line added to a block, or a label added to an Input, fails it until both sides agree.
- The word caps of the shipped prompts and the byte caps of the read sets of `plan-author`, `task-coder`, `task-reviewer` and `hunter` are `cap/*` rules in `tools/lint/data/caps.ts`, run by the lint job: growing a file or section they read fails it until the cap is raised on purpose.
- `replay/plan-review/` holds three plans recovered from archived runs (kept as recorded but for the names of retired agents, which the stale-reference sweep forbids, so one may fail a later `plan-index.sh` check; `plan-c.md` leaves out the slice of its run that changed an agent file the plugin does not ship), what the plan judge and the reach search must report for each (`expected.md`) and the by-hand comparison procedure (`README.md`); no test reads it, yet the stale-reference sweep reads all of it.
- `replay/done-clauses.md` is the sample of done clauses (`bad` ones that break a test rule, `good` ones that hold, `read` ones that hold with no test) for a by-hand replay against the plan author and the coder; no test reads it, and it carries no name or text of a customer project.

## Change together

- `viber/hooks/hooks.json`: `kill-guard.test.ts` pins the `PreToolUse` entry (matcher `Bash`, run through `bash`), `shell-guard.test.ts` its second `Bash` entry and `verdict-nudge.test.ts` the `SubagentStop` entry, `guard-prose.unit.test.ts` the `Edit|Write` entry of `file-guard.sh`, `plan-gate.test.ts` asserts the description names `planning.outside-plan-review`, `session-start.test.ts` asserts it names the schema note.
- `viber/skills/setup/templates/viber.yml`: no test binds the template to the defaults `config` resolves; `bootstrap.test.ts` binds the template's key list to its `schema:` number in `SCHEMA_KEYS`, so a key layout change needs a new schema number and its `SCHEMA_KEYS` entry.
- `task-step.test.ts` runs a copy of the plugin: the copy holds `config.ts`, `run-failures.ts`, `plan-index.ts`, `task-ready.ts` and the whole `viber/lib/` beside `scripts/`, or `config.sh` and `run-failures.sh --lessons` print nothing.
- `viber/skills/setup/templates/gitignore.txt` and `settings.json`: `bootstrap.test.ts` and `merge-settings.critical.test.ts` compare written files to them byte for byte, `settings-template.unit.test.ts` holds the shape of `settings.json`, and `bootstrap.test.ts` requires the `.temp/` and `.claude/viber.local.yml` lines in `gitignore.txt`.
- `viber/skills/planner/templates/spec-lite.md` and `spec-full.md` both keep the four anchor lines the plan-index core reads: `## Goal`, `## Acceptance criteria`, `### File map`, `### Out of scope`.

## Traps

- `lens-map-signals.test.ts` lifts every fenced `bash` block of a lens's `<lens>.signals.md` verbatim, replaces `<scope>` (the only placeholder a block may hold) by `.` and runs it in a throwaway repository: exit 0, or exit 1 with empty stderr, passes. Git accepts a malformed `--since` with exit 0 and an empty log, so only its fix-history window case (a 5-day-old fix listed, a 400-day-old one and a non-fix commit left out) proves the window real. Without a bash on `PATH` the cases skip and pass vacuously.
- The stale-reference sweep of `code-auditor.unit.test.ts` reads the git index and assembles its `FORBIDDEN` tokens from fragments so it passes over itself: an untracked file is not swept, and a token written whole in that test file would flag it.
- `session-start.test.ts` and `plan-hints.test.ts` compare the injected context to `viber/hooks/content/manifest.md` and `plan-hints.md` with trailing newlines trimmed: editing the content needs no test change, editing how it is emitted does.
- The auditor script tests (`strip-tag`, `frame`, `map-signals`, `keep-units`, `hunt-return`, `synthesize`) build every closing-tag fixture from escapes, so the `orphan-tags/tracked` rule passes over them.
- A section cut by `section()` ends on its kept newline, so a line count of one holds one more empty string than the text shows.
